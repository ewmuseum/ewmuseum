# THE E-WRESTLING MUSEUM

> **DRAFT public-grade revamp (2026-08-22)** — awaiting the Janitor's
> editing pass before the open.

Canonical repository: **github.com/ewmuseum/ewmuseum** — mirrors listed
in docs/OPERATIONS.md. The site the repo renders: **ewmuseum.org**.

A static site preserving fantasy wrestling history — play-by-mail,
tabletop, Prodigy, Usenet, the web, and every other form the hobby took.
Promotions arrive one at a time, each documented as deep as the record
allows. Its deepest connected history so far is the IWF line — **IWF (1998)
→ GIWF (1999–2001) → UWF (2001)/XUW (2001) → UiWF (c. 2008–2009)**, plus two
later rooms still in preparation — but every index page is a flat,
alphabetical (or, for shows, chronological) list with search and filters,
never a grouping that bakes in whichever collection got here first. A 500th
promotion costs the same, and sorts on the same terms, as the first eleven.

The museum's dedications — **Sean Simon Williams (1985–2018)** and
**Jaymes Faulkner (1972–2022)** — are kept on their own memorial hall
(`/in-memoriam.html`), open to more names than theirs.

> This repository lives **outside** the game repo on purpose. The Museum is a
> preservation project, not part of the Wrestling With Vibes engine.

## What it is

Plain HTML/CSS. No framework, no build step — readable and editable by any
future contributor, human or AI. It's a **portal, not an essay**: the
homepage names no promotion and leads only to category doors. The whole site
is:

```
index.html              The portal (category doors, no promotion named)
promotions.html         Every promotion, flat & alphabetical, search + filter
frontier.html            Promotions named in the record but not yet held
characters.html            Every character/unit, flat & alphabetical — a hand-
                         maintained instrument page (fetches
                         data/characters-index.json, generated by
                         scripts/cross-reference.mjs, at runtime)
championships.html       Every title, flat & alphabetical, promotion inline
reigns.html               Every title reign, one row per reign — same
                         instrument shape as matches.html, over
                         data/reigns-index.json; rows link the title's own
                         page and the show a reign was won on
shows.html                Every served show, strictly chronological
matches.html               Every match, one row per bout, search + filter —
                         same instrument shape as characters.html, over
                         data/matches-index.json (every show's own
                         matches[]); no per-match pages, every row links to
                         its show
appearances.html          Every show presence (matches AND angles), one row
                         per data/shows.json appearances[] entry, over
                         data/appearances-index.json — the largest index on
                         the site
awards.html               Every award entity, plus a second bestowal-level
                         search underneath (over data/awards-index.json)
essays.html / essays/    Writing about e-wrestling, as a distinct datatype
                         from database records (data/essays.json): outside
                         pieces, linked or served, and the museum's own
                         essays, e.g.
                         essays/all-fantasy-wrestling-is-beautiful.html
in-memoriam.html          The memorial hall
search.html               Client-side search over data/*.json (vanilla JS)
js/list.js                 Shared list/filter/sort helper — every index page's
                         search box, typeahead filter, and sort-key/acronym
                         (name-year disambiguation) logic lives here once
collections.html, who.html   Meta-refresh stubs at the old URLs (renamed to
                         promotions.html / characters.html)
promotions/{iwf,giwf,uwf,uiwf}/   Per-fed pages: era, titles, roster, shows, archive
orbit.html                Meta-refresh stub (redirects to promotions.html) —
                         every fed it used to profile (XUW, PTC, PCW, OSW,
                         ADW) has its own wing now; this line was stale
curation.html             The constitution, in plain language
about.html                What the Museum is, and who it's for
style.css                 The one shared stylesheet
functions/_middleware.js  The invite gate (Cloudflare Pages Function)
data/                     The registry — promotions, characters, units, titles,
                          shows, essays, memorials, affiliations, frontier,
                          aliases, review-queue, wanted (see below)
scripts/validate.mjs           CI check: link + house-rule checker
scripts/registry-validate.mjs  CI check: registry consistency checker
scripts/cross-reference.mjs    Regenerates characters.html + auto-links entity
                                mentions on curated pages (never inside
                                promotions/*/archive/*.html — those are served verbatim)
```

Read **[the curation page](https://ewmuseum.org/curation.html)** before adding anything. It is short and it
is binding.

## The law and the craft

**[The curation page](https://ewmuseum.org/curation.html) states the LAW** — what's allowed, what's
forbidden, and why. It
governs privacy, verbatim-serving, evidence grading, and every other
constraint that would be expensive to get wrong. Read it in full before
any work; it does not change without a real ruling.

**[`docs/`](docs/) is the CRAFT** — the handbook, written from this
project's own history of what broke and why, so a stranger (human or a
future Claude with no memory of this session) can run an accession from
the repo alone:

- **[`CLAUDE.md`](CLAUDE.md)** — the entrypoint; what this repo is, the
  three sacred reads, the standing invariants, the file map.
- **[`docs/PROCESS.md`](docs/PROCESS.md)** — the accession pipeline end to
  end: intake, mining, digests, serving, registry, cross-referencing,
  prose, QA, the wave-report format.
- **[`docs/SCHEMA.md`](docs/SCHEMA.md)** — every `data/*.json` shape,
  field by field, with a real example row.
- **[`docs/OPERATIONS.md`](docs/OPERATIONS.md)** — hosting, the gate,
  mirrors, cache/version-stamp conventions, the maintenance calendar.

The handbook changes by experience, no ceremony required, whenever a
script breaks or a recipe gets faster or a doc turns out wrong. The law
changes only by gavel.

## The gate

Every request passes through `functions/_middleware.js` — an HMAC-signed cookie
gate adapted near-verbatim from the game's proven middleware. Two environment
variables (set as Cloudflare Pages **secrets**, never committed):

- `GATE_SECRET` — signs the admission cookie. Change it to log everyone out at
  once.
- `INVITE_CODES` — comma-separated invite codes, case- and whitespace-insensitive.

Rotate access by editing `INVITE_CODES`; there is nothing else to redeploy.

## Local check

```sh
export PATH="$HOME/.local/opt/node/bin:$PATH"
npm run check             # site check + registry check (what CI runs)
npm run check:site        # link + house-rule check only
npm run check:registry    # data/ consistency check only
npm run refresh:links     # regenerate characters.html + entity links after editing
                           # data/characters.json or data/units.json
```

## The entity registry

`data/` holds the Museum's structured registry — every character, unit,
title, show, essay, memorial and promotion the collection has surfaced, one
JSON file per type. It has its own doctrine (slugs as identifiers, no
auto-merge, no silent distinctness, evidence-graded identity assertions, a
review queue for duplicate candidates, per-collection provenance and
visibility) — see **[the registry rule](https://ewmuseum.org/curation.html#the-registry)** before editing it.
`essays.json` is curatorial/narrative writing (distinct from the database
records everything else in `data/` holds); `memorials.json` backs the
memorial hall and is governed by the privacy rule's presumption-of-welcome
clause, not the ordinary privacy default.

`scripts/cross-reference.mjs` reads the registry and auto-links entity
mentions on curated pages (never inside a served verbatim artifact document),
regenerating `characters.html` and `data/wanted.json` (names seen in prose that
match no entity — the mining wish-list) each time it runs. Run it again after
any registry edit; `npm run check:registry` will catch a stale or broken
result either way.

## Deploy

Build-less: the served tree is this repository's own files, no build
step. It lives in the R2 bucket `ewmuseum-site`, and the Worker
`ewmuseum-serve` (`worker/index.mjs`, configured by `worker/wrangler.toml`)
serves it on the museum's domains, carrying the pretty-URL routing, the
`_headers` policy (baked into `worker/headers.json` by
`npm run worker:headers`) and the site search.

- **The tree**: `npm run r2:sync` (`scripts/r2-sync.mjs`) uploads only what
  changed since the last sync (a path → sha256 manifest kept in the
  bucket), and refuses to run without a clean tree and a green gate
  stamp; `npm run r2:dry` prints the diff and changes nothing. The cycle's
  chain (`scripts/ops/chain.sh`) runs it after each green, committed gate.
- **The Worker**: `npm run worker:deploy`
  (`npx wrangler deploy -c worker/wrangler.toml`, from the repo root). Its
  secrets are set with `npx wrangler secret put -c worker/wrangler.toml
  <NAME>` and are never committed; `npm run worker:test` runs its parity
  and sync tests against a local Worker and a local bucket.

### CI / GitHub Actions

`.github/workflows/ci.yml` runs `npm run check` on every push and pull
request; it deploys nothing. `.github/workflows/deploy-r2.yml` is a manual
(workflow_dispatch) sync that stays inactive until the repository variable
`R2_DEPLOY` is set. The old Cloudflare Pages deploy was retired on
2026-08-29, when the museum outgrew Pages' 20,000-file limit.

## Where the museum lives

**GitHub (`ewmuseum/ewmuseum`) is canonical.** Every push to `main`
force-syncs, whole (`.github/workflows/mirror.yml`), to any configured
mirror remote (GitLab, Codeberg, ...) — those are **read-only replicas**,
not additional homes. Never push directly to a mirror; a mirror's own
history gets silently overwritten by the next sync from GitHub regardless,
so a direct push there is invisible work.

If GitHub itself ever dies: promote whichever mirror is most current to
canonical, repoint `mirror.yml` (and CI/Cloudflare Pages deploy) at the new
home, and carry on — the mirrors exist so that decision is a repoint, not a
reconstruction.


## Contributing

The website is read-only forever — **every write happens here, at the
git level**, and the site deploys what was written. If you played,
ran, or archived an e-fed and want its history kept: see
[CONTRIBUTING.md](CONTRIBUTING.md). If you appear in this material and
want something removed or de-identified, you don't need a reason and
you won't get an argument: open a takedown issue (a template is
provided) or reach the curators any way you're able — see the
[Takedown & Privacy Policy](https://ewmuseum.org/curation.html#takedown-policy).
